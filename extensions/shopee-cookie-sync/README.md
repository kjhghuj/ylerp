# 阳零 ERP · Shopee 凭据同步

首次用 ERP 账号密码登录，之后点击「开始同步」，即可更新当前 ERP 账号下所有店铺共用的 Cookie 和 SPC_CDS。无需配对码，也无需注册浏览器。

## 安装

1. 解压 `shopee-cookie-sync.zip` 到一个固定目录。
2. 打开 Chrome 的扩展程序管理页面 `chrome://extensions/`。
3. 打开右上角「开发者模式」，点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的解压目录。
4. 将「阳零 ERP · Shopee 凭据同步」固定在 Chrome 工具栏。

开发者也可以加载生成的 `dist/unpacked` 目录。ZIP 是解压用的安装包，不是 Chrome 商店 CRX 文件。

更新到 **1.0.5**：若加载的是项目内 `dist/unpacked`，在扩展管理页点击「重新加载」；若之前自行解压了 ZIP，请先用新版 ZIP 覆盖原解压目录，再重新加载。插件右上角应显示 `v1.0.5`。Chrome 若提示新增生产网站访问权限，请允许访问 `http://39.97.246.43/`。重新加载后，打开或刷新 `https://seller.shopee.cn/`，插件会重新捕获凭据；捕获失败时会显示具体原因。

1.0.5 新增环境选择：弹窗顶部选择「开发环境」或「生产环境」，点击「切换环境」保存。默认使用开发环境 `http://localhost:4022/api`，生产环境为 `http://39.97.246.43/api`。重新打开插件或重启浏览器会保留选择。切换环境会退出 ERP 登录并清除旧同步结果，需要使用所选环境的账号重新登录；同步进行中暂时不能切换。

1.0.4 修复权限漏读：Chrome 按 Cookie 的 Secure 属性检查 HTTP/HTTPS 来源，Shopee 的两个允许域名现均声明两种来源权限，以读取完整的普通 Cookie 和 Secure Cookie。卖家中心请求捕获仍限定 `https://seller.shopee.cn/api/*`，ERP 地址仍按配置生成。

1.0.4 同时增加 Cookie 不匹配的诊断：显示请求与浏览器的 Cookie 数量、SPC_CDS Cookie 的匹配结果，以及缺失、额外或发生变化的 Cookie 名称。诊断不会保存或显示 Cookie 值、SPC_CDS 参数值或完整请求网址；反馈问题时只需复制提示文字。若 Chrome 在更新后提示重新允许网站访问，请允许这两个 Shopee 域名。

1.0.3 修正动态 Cookie 造成的误报：当请求参数、请求头和当前 Cookie 中的 `SPC_CDS` 唯一且一致，并且当前快照包含请求的所有 Cookie 名称及同名数量时，点击同步会从同一次当前 Cookie 读取中取得完整凭据。其他 Cookie 值更新或新增 Cookie 不再阻止同步；SPC_CDS 变化、消失、冲突，或请求中的 Cookie 被删除时，需要重新捕获。没有匹配的 SPC_CDS Cookie 时，继续使用完整请求指纹校验。

## 使用

1. 在插件顶部选择上传环境并点击「切换环境」。开发环境需要启动本地 ERP 后端；生产环境使用 `http://39.97.246.43/api`。
2. 打开插件，用 ERP 用户名和密码登录。插件只保存 token，不保存密码；现有 ERP token 有效期 7 天，过期后重新登录。
3. 打开 `https://seller.shopee.cn/`，登录后进入卖家中心。插件从 API 请求里的 `SPC_CDS` 参数自动获取凭据。
4. 插件显示「SPC_CDS 已自动捕获」后，点击「开始同步」。无需复制 Cookie-Editor JSON 或网络请求参数。
5. 到 ERP 商品分析的「采集店铺数据」选择日期开始采集。店铺 ID 仍需各店铺单独绑定；共用登录账号必须具有目标店铺权限。

多个浏览器可用同一个 ERP 账号登录，以最后成功上传的凭据为准。上传完成不等于已验证 Shopee 登录有效，ERP 在真实采集请求时验证。

## 常见情况

- **没有捕获 SPC_CDS**：安装或更新插件后打开或刷新卖家中心，触发新的 API 请求。如果仍然未捕获，请查看插件捕获状态区域显示的具体原因并按提示处理；反馈问题时只需提供这段提示，不要发送 Cookie 或 SPC_CDS。插件不会主动刷新你正在操作的页面。
- **登录状态已变化 / 候选已过期**：重新打开或刷新卖家中心。候选有效期 30 分钟，浏览器重启后需要重新捕获。
- **无法连接 ERP**：确认弹窗显示的环境和接口地址正确，开发环境检查后端是否在 4022 端口启动；生产环境检查服务器是否可访问及 Chrome 是否允许生产域名访问。网络失败不会清除已有 ERP 登录状态。
- **ERP 登录过期**：重新登录。权限不足时保留登录状态并提示，需账号具有商品分析上传权限。
- **关闭弹窗**：已经启动的上传会在后台继续，重新打开可查看结果。
- **无痕 / 分区 Cookie**：第一版不支持，请使用普通 Chrome 窗口。

插件权限仅包括读取 Shopee Cookie、观察卖家中心请求、保存扩展状态，以及访问配置中的 ERP 域名。Cookie 不持久保存；SPC_CDS 只在当前浏览器会话的扩展存储中保留。不会把 Cookie、SPC_CDS 或密码写入日志。

## 开发与地址配置

需要 Node.js 22 或更新版本，无需安装第三方依赖。

```text
cd extensions/shopee-cookie-sync
npm test
npm run build
```

开发和生产地址集中在 `config.mjs` 的 `ERP_API_BASE`、`ERP_PRODUCTION_API_BASE` 常量，安装包会同时声明这两个环境的域名权限，日常切换无需重新打包。修改地址后重新运行构建，域名权限会自动更新。也可仅覆盖本次构建的开发地址：

```text
npm run build -- --api-base http://localhost:4022/api
```

地址配置变更后重新安装或在扩展管理页点击「重新加载」。当所选环境的 API 地址发生变化时，插件会清除旧地址的 ERP 登录状态，需要重新登录。除本地地址及配置中的生产 HTTP 来源外，其他远程地址必须使用 HTTPS；地址不能包含账号、查询参数或片段。当前生产地址按要求使用 HTTP，密码、token 及同步凭据传输没有 HTTPS 加密，后续可将生产常量改为服务器的 HTTPS 地址并重新构建。

第一版只在点击时同步，不包含每日自动任务，也不会自动提交商品报表采集任务。
