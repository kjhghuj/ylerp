# 补货工作台（店铺补货 · 补货V3）使用说明

> 面向使用者。补货工作台把「商品分析店铺的销量」与「元仓仓储库存」直接关联，自动完成大部分商品的关联与计算，你只需要处理少量异常、确认数量并保存计划。

## 核心概念

| 概念 | 含义 |
|---|---|
| 店铺 | 需求来源。可多选同站点店铺（共仓模式：各店需求汇总后扣一次库存）。 |
| 库存池 | 供应来源（一组仓库编码）。未选择时默认扣减站点全部仓库，并给出提示。 |
| 最终补货 SKU | 计算单位。多个平台规格货号可指向同一补货 SKU，需求自动合并。 |
| 规格货号 | 商品分析报表变体中的「规格货号」（modelCode），与元仓 customerSku 同一套编码。 |

## 自动关联顺序（无需人工）

1. **店铺专属映射**：你在待核对区确认过的映射（只对本店生效）。
2. **元仓同码直连**：规格货号与元仓 customerSku 完全一致且唯一 → 直接关联，**没有本地商品/库存档案也能计算**（成本显示“未知”）。
3. **站点级历史映射**：补货V2 已建立的映射继续生效。
4. 以上都不满足 → 进入**待核对**（模糊候选仅参考，必须人工确认）。

## 数据口径

- **日销 = 已下订单件数 ÷ 统计天数**。统计天数默认 = 区间内店铺实际上传天数；可在参数抽屉“高级设置”自定义（会标记为人工覆盖）。
- 每行都有数据质量状态：正常 / 观测不足（<3 天，受限估算）/ **数据过旧（最新观测早于计划日 7 天以上 → 不可执行）** / 真实零销量 / 无有效观测（不可执行）。
- **元仓零库存 ≠ 库存未知**：元仓返回该货品且可用库存为 0 → 正常计算（可能建议补货）；元仓未返回该货品 → 「库存未知」（表格显示“未知”而非 0），**不可执行**——不能勾选、不能填确认量、不能保存。
- **在途按 ETA 分类**（需求区间为左闭右开，目标日当天到货不计入）：到仓前/覆盖期内（计入）；无 ETA、已逾期、覆盖期后（不计入确定供应）。

## 建议量公式（第二轮：按到货时间推导，详情抽屉展示双轨迹）

```
预测日销   = 有效日销 × (1 + 增长%)
基线轨迹   = 不新增补货时的逐日库存（丢失销量假设：断货日未满足需求损失）
建议补货量 = 到仓后缺口（基线轨迹中 到仓日~目标日 的未满足需求）
           + 期末安全库存缺口
```

- **晚到的在途不会提前抵扣建议量**：系统按供应实际到达时间逐日推导，建议量、状态、轨迹图、导出同源一致。
- 详情抽屉展示两条轨迹：「采用建议量后」与「不新增补货时（对照）」，并分列三类缺口：
  - 到仓前缺口（丢失销量，本次订单无法修复，状态=断货风险）
  - 到仓后缺口（由本次建议量覆盖）
  - 期末安全库存缺口
- 映射冲突（如元仓同码与历史映射指向不一致、历史映射多目标）是**阻断状态**：该货号不参与计算，必须在待核对区人工裁决。

## 保存计划（服务端快照）

保存时只提交：结果 ID、所选可执行 SKU、人工确认量/调整原因、名称。服务端据此生成**完整不可变快照**（销量来源、逐仓库存、在途明细、质量、计算中间值、匹配依据），摘要只按保存项重算，建议金额与确认金额分列。

- 确认量 ≠ 建议量时**必须填写调整原因**（前端拦截 + 后端校验）。
- 数量只接受非负整数（1.5、1e3 等输入直接拒绝）。
- 不可执行项（库存未知/零销量/数据过旧）不能保存；手工填数量也无法绕过。
- **整站仓库范围（未选库存池）只能保存草稿预览；确认计划必须使用库存池或明确仓库范围。**
- 保存带幂等键：双击/重试不会产生重复计划；草稿编辑/确认/作废带版本号防并发冲突。
- 确认时按**仓库范围重叠 + SKU 交集**提醒重复安排；已确认计划可「复制为新版本」（历史保留）。

## 操作流程

1. 顶部选择店铺（可多选共仓）、区间（近7/14/30天或自定义）、库存池。
2. 点「计算补货建议」。正常商品直接出结果；点状态条「待核对 N 项」处理异常（选候选 → 保存映射 → 重新计算）。
3. 主表筛选（需补货/断货风险/库存未知/全部）、搜索、排序、翻页；点行看**详情抽屉**（来源、质量、逐仓库存、在途明细、逐日模拟、计算过程）。
4. 在「确认补货量」列填写人工数量（留空 = 采用建议量）；勾选参与本次计划的 SKU。
5. 底部操作栏：**保存计划**（草稿，含完整条件快照）→ 计划列表中**确认**（可导出）或**作废**（需填原因）。
   - 「确认」只表示补货安排被批准，**不等于已下单，不会计入元仓在途**。
   - 确认时若同站点已有包含相同 SKU 的未作废已确认计划，会提示重复安排。
6. **导出**：从已保存计划导出的 CSV 与保存版本完全一致（含计划号、口径、条件指纹）；「导出当前结果」只在结果未过期时可用。

## 结果过期规则（防止拿旧结果当新条件用）

店铺、区间、库存池、任何参数、映射或规则发生变化后，当前结果立即标记**过期**，复制、导出与保存按钮全部禁用，需点「重新计算」。

- **刷新源数据**：强制重新拉取销量与元仓库存/在途（含货品清单缓存）。刷新失败时旧结果保留展示但明确标注属于旧快照，保存/导出/复制同样禁用，直到刷新或重算成功。
- **重新计算**：只改参数时复用同一份元仓快照重算（状态条显示“元仓 快照”与真实拉取时间），不重复全量拉取。
- 导出分两个按钮：「导出全部」= 全部核对结果（含不可执行项的状态标注）；「导出所选（可执行）」= 仅勾选的可执行 SKU 补货清单。

## 待核对区

- 状态分「待匹配」（无依据）与「冲突」（依据矛盾：元仓同码 vs 历史映射不一致、多目标映射、编号类型歧义等）——**冲突必须人工裁决**，系统不会自动采用任何一方。
- 支持按货号/商品名搜索、分页，并可搜索**全部元仓货品**作为映射候选。
- 名称/前缀相似候选仅供参考（匹配度百分比），保存映射需人工确认；已匹配的商品可在详情抽屉「删除映射（恢复继承）」。

## 与补货V2（表格补货）的关系

- 站点级映射与站点级 SKU 规则两版互通；补货工作台默认写**店铺级**（不影响的 V2），可选择存为站点级。
- V2 的计算口径完全未变（本升级对其引擎零影响，回归测试全部通过）。
