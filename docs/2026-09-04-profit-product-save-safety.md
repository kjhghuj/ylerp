# 利润计算保存到商品明细：防止覆盖其他商品

## 问题与目标

旧逻辑优先按 `profitEditingProductId` 更新商品，即使表单名称、SKU 已经改变。
重置表单不会清除该 ID，无 ID 的导入也不会解除旧绑定。未绑定 ID 时，又会按名称与 SKU 自动查找商品并更新。

目标：每次写入都能明确区分新增与更新，用户复用 A 的表单计算 B 时，A 及其利润模板不会被意外修改。

## 实施计划与完成情况

1. **完成：明确保存意图。**
   - 新增只调用 `POST /products/with-templates`。
   - 更新只调用 `PUT /products/:id/with-templates`，目标必须是当前绑定且在商品列表中存在的商品。
   - 删除名称和 SKU 自动匹配并更新的分支。
   - 新增或另存遇到已有 SKU 时阻止保存；更新也不能占用其他商品的 SKU。
2. **完成：增加保存选择。**
   - 显示当前编辑商品的原名称、SKU，或新增状态。
   - 编辑状态提供“更新当前商品”和“另存为新商品”。
   - 名称或 SKU 去除首尾空格后发生改变，更新前显示原信息和当前信息。
   - 支持确认修改原商品、另存、取消；Escape 取消，焦点保留在对话框内并在关闭后恢复。
3. **完成：修复状态与关联。**
   - 重置清除编辑 ID、计算节点、校验错误和待确认操作，并清空原有基础字段及站点输入。
   - 无 ID 的导入进入新增状态，不继承旧编辑 ID。
   - 另存请求不读取 A 的模板关联；只创建新关联。
   - 另存成功后移除各站点节点的旧 `productId`、`productTemplateLinkId` 及旧关联形式的 `templateId`；保留合法共享模板 ID 和计算数据。
   - 保存成功后绑定服务端返回的商品 ID，使后续修改成本、价格或站点参数能够继续更新该商品。
4. **完成：保护异步操作。**
   - 请求期间禁用保存按钮，并使用同步锁阻止重复提交。
   - 保存失败保留表单和编辑 ID，允许重试。
   - 表单重置、编辑、切换商品或组件卸载后，旧请求不得重新写回表单及编辑 ID。
   - 确认操作与表单版本、目标 ID、原信息和当前信息绑定；过期确认不能授权其他修改。
   - HTTP 409 显示冲突提示，不回退为更新其他记录。
5. **完成：增加回归测试与检查。**
   - 使用真实 `StoreProvider`、利润计算页面和导入 Hook，API 使用 mock；不访问真实数据库。
   - 新增 19 个页面级场景，验证实际 POST/PUT 路径、商品列表及本地存储。
   - 与现有保存、模板关联测试一起执行，共 82 项通过。
   - TypeScript 检查通过；Vite 生产构建通过。

## 验收场景

| 操作 | 预期 |
| --- | --- |
| 新建并保存 A，改名称、SKU 为 B，点击更新 | 出现保存方式选择；选择另存后同时保留 A、B |
| 载入 A，只修改名称，点击更新 | 需要确认，不静默覆盖 |
| 载入 A，改为 B，确认修改原商品 | 仅在明确确认后按 A 的 ID 更新 |
| 载入 A，重置，再填写 B | 清除旧 ID，新增 B |
| 新增表单输入已有 SKU | 提示冲突，不调用更新接口 |
| 只修改 A 的成本或利润参数 | 正常更新 A，无身份变更对话框 |
| 另存 B 后继续修改利润参数 | 只更新 B 和 B 的模板关联 |
| 更新目标已经失效 | 提示重新载入或另存，不自动创建记录 |
| 保存失败 | 保留表单和原绑定，可以重试 |
| 连续点击保存 | 同时最多一个保存请求 |
| 保存 B 期间重置或载入 C | 旧请求结束后不恢复 B 的表单或绑定 |

## 验证命令

在 `frontend` 目录运行：

```text
npm test -- --run __tests__/ProfitCalculator.saveSafety.test.tsx __tests__/profitHooksPersistence.test.tsx __tests__/StoreContext.atomic.test.tsx __tests__/productTemplateSync.test.ts
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

后端已有用户范围内的 SKU 唯一约束，以及商品和模板的事务保存，本次继续使用。
此次修改不会自动恢复此前已被覆盖的历史商品，也未执行数据库数据修改。
